# Changelog

Written by hand, for humans (plan 09 §9.3): one section per release with what
is new, what you must know, and every breaking change together with what you
must do about it. An autogenerated commit dump is not a changelog, which is why
GoReleaser's generated notes are switched off.

## v0.1.0 - "Cron som husker" (not released yet)

First public release. paceq replaces cron for scheduled jobs, and answers the
question cron never could: why did it not run?

### Nytt

- `paceq init` writes a working project in one command: config, an example job
  and the state database, kept private and out of git.
- Schedules with any time zone and an explicit DST policy; sensors with a
  cursor and run-key deduplication over a frozen subprocess contract.
- Multi-step jobs with static DAG `needs`, retry with backoff, replay of past
  runs, and concurrency keys so overlapping triggers cannot stampede.
- Decisions tested against reality: kill-and-restart chaos sweeps over real
  SQLite state, property-tested sensor cursors, fuzzed parsers.
- `paceq doctor`, `paceq validate`, `paceq fsck` and `paceq logs` to find out
  what is wrong instead of guessing.
- One static binary per platform (linux/amd64, linux/arm64, darwin/amd64,
  darwin/arm64), no runtime, no Docker, no package manager. Every release
  carries sha256 checksums, is built reproducibly (the same tag built twice
  must produce identical bytes), and install.sh verifies before it installs.

### Du må vite

- The delivery guarantee is at-least-once, not exactly-once:
  docs/guarantees.md has the guarantees, the non-guarantees and the invariants.
- The database format is not frozen until v1.0, but migration from v0.1
  forward is guaranteed.
- Windows is not a supported platform: unix sockets, process groups and flock
  are load-bearing parts of the design.
- Verify your download: `sha256sum -c checksums.txt --ignore-missing`.
